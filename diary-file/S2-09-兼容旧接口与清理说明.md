# S2-09：旧接口下线、可靠删除与后台清理

## 目标

- 删除旧的 `POST /file/upload/images` 整文件上传入口及节点本地异步上传链路。
- 所有业务前端统一使用分片、秒传、断点续传和进度回调能力。
- 图片删除不再先删 OSS、再硬删数据库。
- 自动清理过期 Multipart 会话、分片记录和已发送 Outbox。

## 上传接口收敛

图片上传只保留 `/file/upload/images/config`、`/init`、`/{uploadId}/chunks/{chunkIndex}`、`/{uploadId}/complete` 四类接口。旧接口对应的 `UploadService`、本地落盘异步上传方法和兼容事务方法已经删除。

时间轴、恋爱记录、食谱和饮食记录均复用前端 `uploadImageFiles`，并已移除各模块中误导性的旧端点常量。图标继续使用独立的 `/file/sys/icon/*` 接口，不属于本次图片分片链路。生活随想页面目前只用 `FileReader` 保存浏览器内的临时展示数据，没有调用后端上传接口。

## 缩略图按需生成与访问

图片类型只区分“需要缩略图”和“不需要缩略图”。当前类型 `1000`（饮食、恋爱记录、时光轴共用）、`2000`（食谱）以及兼容历史时光轴的 `9000` 需要缩略图：完整文件校验后先进入 `UPLOADED`，由 Outbox + RocketMQ 生成并确认缩略图后进入 `READY`。其他类型校验成功后直接从 `UPLOADING` 进入 `READY`，不写 `IMAGE_UPLOADED` Outbox，也不产生 `thumbnail` 数据。

卡片页通过 `POST /file/query/thumbnails/urls` 批量查询当前用户可访问的缩略图地址，再通过 `GET /file/thumbnails/{imageId}` 流式读取缩略图；详情页继续查询和显示原图。批量查询在数据库中一次完成用户、状态和类型校验，避免N+1查询；单图读取再次执行权限与状态校验，不向前端暴露OSS objectKey。

原图通过 `GET /file/originals/{imageId}` 直接从OSS流式返回。节点本地图片缓存和批量下载到节点目录的接口已经删除；历史 `/file/images/{fileName}` 地址只保留兼容读取，内部同样不再落盘。

缩略图不再使用额外全表扫描进行兜底恢复。`session COMPLETED + image UPLOADED + IMAGE_UPLOADED Outbox` 已经在同一数据库事务提交，常驻扫描会重复主链路职责。历史脏数据需要修复时使用一次性脚本或人工重放事件。

饮食记录新增 `image_id BIGINT UNSIGNED NOT NULL DEFAULT 0`，旧数据统一保留为 `0`。人工迁移脚本位于 `diary-diet/src/main/java/diary/diarydiet/sql/diet_image_id_migration.sql`。

## 可靠删除

`POST /file/delete/{imageId}` 使用当前登录用户作为权限边界。在公共事务 Service 中完成：

1. 使用 `SELECT ... FOR UPDATE` 锁定所属图片。
2. `image.deleted = 1`，同时将 `sha256` 清空以释放唯一索引。
3. 将对应 `thumbnail` 逻辑删除。
4. 插入唯一 `IMAGE_DELETED` Outbox。

事务中不调用 OSS 或 RocketMQ。`ImageDeleteConsumer` 收到事件后幂等删除原图及缩略图；临时失败返回 `FAILURE`，交给 RocketMQ 重投。

## 过期会话清理

`ImageUploadSessionCleanupScheduler` 每次按配置读取有限数量候选：

1. 对 `INITIATING/UPLOADING` 且已过期的会话使用 `status + version` CAS 改为 `EXPIRED`。
2. 在数据库事务外调用 OSS Abort Multipart Upload。
3. Abort 成功后，在公共事务中删除分片、删除会话，并逻辑删除未完成图片及清空 SHA-256。
4. 对已经是 `EXPIRED` 的记录继续重试，覆盖上次 OSS 网络失败的情况。
5. 每轮额外批量删除不存在所属会话的孤儿分片。

分片写入 SQL 会再次检查会话仍为 `UPLOADING` 且未过期，封闭“OSS Part 上传期间会话被清理”的并发窗口。

## 配置

配置样例位于 `src/main/resources/a`：

```yaml
diary:
  file:
    image-upload:
      cleanup-interval-ms: 60000
      cleanup-batch-size: 20
    rocketmq:
      image-deleted-tag: IMAGE_DELETED
      image-cleanup-consumer-group: diary-file-image-cleanup-consumer
```

项目运行时从 Nacos 导入 `diary-file.yaml`，因此必须把上述配置同步到 Nacos；文件 `a` 本身不会被 Spring Boot 自动加载。

## 运维观察项

- 长时间处于 `EXPIRED`：通常表示 OSS Abort 持续失败。
- `IMAGE_DELETED` 长时间处于 `RETRY_WAIT/DEAD`：表示 OSS 对象清理失败。
- `image_upload_chunk` 持续增长：检查清理调度是否启用以及数据库账号是否拥有 DELETE 权限。
- Outbox 的 `SENT` 仅表示 Broker 已接收，不代表业务消费者执行完成。
